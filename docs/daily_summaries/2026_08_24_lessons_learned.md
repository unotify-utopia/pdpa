# PDPA Application - ถอดบทเรียนการทำงานรายวัน (Lessons Learned)
**วันที่:** 24 สิงหาคม 2026 (2026-08-24)

## สรุปภาพรวมงานที่ทำ
ในวันนี้เราได้ทำการปรับปรุงและแก้ไขปัญหาระบบ PDPA App ทั้งในฝั่ง Sandbox (Single Node) และฝั่ง Production (Multi-Tenant) โดยเน้นไปที่การทำให้ทั้งสองเซิร์ฟเวอร์สามารถใช้ **Source Code (Branch: main) ชุดเดียวกันได้** แต่แสดงผลและทำงานแตกต่างกันตามการตั้งค่าของ Environment (`.env`) ได้อย่างสมบูรณ์แบบ 100%

## บทเรียนที่สำคัญ (Key Lessons Learned)

### 1. ลำดับความสำคัญของ SQL (SQL Precedence Bug)
- **ปัญหา:** API เส้น `GET /api/public/tenants` คืนค่ารายชื่อหน่วยงานทั้งหมดออกมา (4 หน่วยงาน) แม้ว่าจะสั่งเปิดโหมด Single Node แล้วก็ตาม ทำให้หน้าบ้านยังคงโชว์กล่องให้ผู้ใช้เลือกหน่วยงาน
- **สาเหตุ:** เกิดจากการเขียนเงื่อนไขผสมระหว่าง `AND` และ `OR` โดยไม่มีวงเล็บกำกับ:
  `WHERE status = 'active' OR status IS NULL AND id = 'default-tenant'`
  PostgreSQL นำไปตีความว่า `(status = 'active') OR (status IS NULL AND id = 'default-tenant')` ทำให้หน่วยงานเก่าที่มีสถานะ 'active' หลุดกรองออกมาทั้งหมด!
- **การแก้ไข:** เติมวงเล็บครอบเงื่อนไข `OR` ให้ชัดเจน เพื่อให้ระบบทำงานตามขั้นตอน:
  `WHERE (status = 'active' OR status IS NULL) AND id = 'default-tenant'`

### 2. ปัญหาตัวแปร .env และการอ่านค่าจากระบบปฏิบัติการที่ต่างกัน (CRLF vs LF)
- **ปัญหา:** ระบบหลังบ้าน (Backend) ทำงานผิดพลาดในเงื่อนไข `if (process.env.SYSTEM_MODE === 'SINGLE_NODE')`
- **สาเหตุ:** ไฟล์ `.env` ถูกสร้างและแก้ไขผ่าน Windows (PowerShell) ทำให้จุดสิ้นสุดบรรทัดเป็นแบบ **CRLF** (`\r\n`) เมื่อนำไปรันบน Ubuntu (Linux) ตัวแปรที่ได้จึงมีค่าเป็น `"SINGLE_NODE\r"` ซึ่งทำให้การเปรียบเทียบค่า String (`===`) ได้ผลลัพธ์เป็นเท็จ (False)
- **การแก้ไข:** เพิ่มคำสั่ง `.trim()` ในทุกที่ที่มีการเช็คตัวแปรจาก Environment 
  `process.env.SYSTEM_MODE.trim() === 'SINGLE_NODE'` เพื่อกำจัด Whitespace หรือ Carriage Return แฝง

### 3. การจัดการ Cache ของ Cloudflare และเบราว์เซอร์
- **ปัญหา:** หลังการแก้ไขโค้ด React (ฝั่ง Frontend) ขึ้นเซิร์ฟเวอร์แล้ว หน้าเว็บของผู้ใช้งานยังคงแสดงผลเหมือนเดิม
- **สาเหตุ:** ไฟล์ JS/CSS Bundle ถูกโหลดเก็บไว้ที่ Cache ของ Cloudflare และ Service Worker ของเบราว์เซอร์ผู้ใช้
- **แนวทางปฏิบัติ:** แนะนำให้ผู้ใช้ทำการ **Hard Refresh** (`Ctrl + F5` หรือ `Cmd + Shift + R`) เพื่อบังคับให้โหลดไฟล์ต้นฉบับ (index.html) ใหม่ 

### 4. กระบวนการออกแบบ One Codebase, Multi-Environment
- **แนวคิด:** แทนที่จะแยก Branch หรือแยก Source Code สำหรับระบบย่อย (Sandbox) เราใช้กลยุทธ์ **"One Codebase"** โดยดึงตัวแปรสภาพแวดล้อม (`.env`) มาเป็นสวิตช์ปิด-เปิดฟังก์ชันต่างๆ 
- **ตัวอย่างการนำไปใช้:**
  1. **ระบบ Single Node:** สั่งเปิดด้วยตัวแปร `SYSTEM_MODE=SINGLE_NODE` ระบบจะล็อก Tenant อัตโนมัติเป็น `default-tenant` และซ่อนกล่อง Dropdown เลือกหน่วยงานทั้งหมด
  2. **ระบบ Bypass OTP/MFA (สำหรับการทดสอบ):** สั่งเปิดด้วยตัวแปร `SKIP_MFA_FOR_TESTING=true` บน Sandbox เพื่อให้การเข้าสู่ระบบไม่ต้องใช้ OTP ในขณะที่ฝั่ง Production จะไม่มีตัวแปรนี้ ทำให้ยังคงความปลอดภัยสูงสุดไว้ตามเดิม

### 5. ระวัง Process ซ้อนกันบน PM2
- **ปัญหา:** การแก้ไขบน Sandbox ช่วงแรกไม่แสดงผล เพราะพอร์ต (3001) ดันไปชนกับระบบเดิม (`pdpa-api`) ที่รันค้างไว้
- **แนวทางปฏิบัติ:** ตรวจสอบ Process ด้วย `pm2 status` อยู่เสมอ หากต้องการตั้งระบบใหม่ ควรแยกชื่อ Process (เช่น `pdpa-single-node`) และปิด Process เก่าที่อาจแย่งการผูก Port เดียวกันเพื่อป้องกัน Nginx Proxy ไปผิดที่

## การอัปเดตระบบที่เกิดขึ้นวันนี้
1. จัดหน้าตาและแก้ไขข้อความบนหน้า **Super Admin** 
2. ซ่อนกล่องเลือกหน่วยงาน (Tenant Selector) บนระบบ Sandbox 
3. แยกฐานข้อมูล `pdpa_single_db` เพื่อให้ Sandbox ลอยตัวเป็นอิสระ 
4. เพิ่มตัวเลือก **"อื่น ๆ (โปรดระบุรายละเอียดเพิ่มเติมในช่องที่ 3)"** ในฟอร์มคำร้อง (Target Databases)
5. รวมความสามารถ (Merge) ระบบทั้งหมดที่แยกซ่อม กลับเข้าสู่ Branch `main` และ Deploy ขึ้นระบบ **Production** อย่างสมบูรณ์และปลอดภัย
